# 阅读状态与预取重构

本次交付将逐章阅读状态、未读下载、离线目录、阅读窗口和图片调度接到同一套稳定页面身份上。应用使用 Coil 3.6.3、Room 2.8.5、KSP 2.3.12；调试包名为 `com.ppxb.miwaku.debug`，可以与原包并存。

## 阅读语义

- 分页模式的最后一页停稳并成功显示后，该章标记已读。
- 条漫末页成功显示，且底部进入实际视口后，该章标记已读。主动跳到章尾同样有效。
- 预取、预组合、窗口重排和末页加载失败不会产生已读事实。
- 回看已读章节可以更新位置，但不会清除已读标记。手动标记未读与从头阅读是独立操作。
- 恢复位置优先按文件名定位，再回退到有效页号；条漫保存页内相对偏移。
- “下载未读”包含没有记录和阅读中未完成的章节，排除完整下载与已有活动任务。已入队后再读完不会自动取消下载。

## 数据与迁移

`core:database` 保存作品、章节、页清单、逐章进度、作品历史指针、下载任务与完成页索引。网络刷新不覆盖逐章进度。目录和离线入口不依赖短期缓存。

逐章进度单独放在 `chapter_progress`。`readAt` 非空表示已读；位置更新不携带可覆盖已读标记的快照。一个应用生命周期内的有序写入者合并连续位置，约一秒周期落库；跨章、退出、退后台、章尾完成和手动标记立即提交。周期使用单调时间。正常保存最多触及对应章节和作品，不再重编码全库 JSON。

读者只订阅当前作品/章节所需状态。Room 仍按表发出失效通知，局部查询、生命周期订阅和去重共同限制 UI 工作量。

首次启动在下载队列启动前导入旧数据。解析和文件检查在事务外进行，完整结果与迁移标记在同一事务提交。旧 SharedPreferences、JSON 和图片保持原位；迁移成功后不再双写旧进度或任务列表。

旧记录只能证明每部作品最后保存的位置，不能证明此前各章已读。未知时间保持未知，浏览历史不会冒充阅读时间。可恢复缓存损坏时跳过该文件，持久输入无法解析时显示迁移失败并保留原数据。每份清单完整解析后才生效，防止导入截断页面列表。

文件与 SQLite 不构成跨系统事务。页面先完成文件写入，再登记索引；章节全部完成后才记为 Completed。启动按文件存在性核对完成记录，不逐页解码；缺失页转为可恢复状态。服务端已不提供的页面（404/410）不重试，章节保留可续传记录。下载取消/移除会将文件移入应用私有 `files/recycle/downloads`，再移除索引，保留恢复副本。

`LibrarySchema.VERSION` 是 schema 的唯一版本来源。改表必须同时追加 `AppMigrations`、提交新导出的 `core/database/schemas/<version>.json` 并补迁移测试；`SchemaMigrationTest` 会拦住漏登记与越界版本。库不做破坏性兜底：缺少迁移时宁可启动失败，也不静默丢弃阅读进度。v1 是首版 SQLite schema，此前数据以 JSON/SharedPreferences 形式由导入流程读取，因此当前没有迁移项。

## 窗口与请求

全部章节摘要用于目录。活跃页面内容保留当前章及邻章，仍可见的内容受保护；前插和裁剪在空闲时提交。纯尾部追加不强行恢复滚动位置。尚未应用的锚点保留到界面确认；显式换章创建新的滚动状态，自然跨章保留原状态。

视口通过稳定 key 解释页面，窗口内全局下标不持久化。布局锚点可以是章节分隔条，阅读进度必须取第一张实际可见图片，两者不能混用。初始化和数据重排采用非阻塞 requestScroll 定位，不阻塞视口监听。

`ReaderPrefetcher` 保留新旧需求交集中的 Job，更新优先级并移除失去用途的需求。`PageImageStore` 统一接纳可见页、邻页、详情预热及下载请求，最多三个活跃图片任务，完成一页立即补位。优先级只影响待执行任务，不反复抢占仍然需要的传输。

每个共享请求由使用者共同持有。最后一个使用者退出时取消 Job 和底层 Call，包括已经开始的响应体读取。正在关闭的请求结束前不会启动同 key 的替代传输。重试与缓存清理暂停新请求入场，在旧传输结束后处理文件；失效和文件发布有共同提交边界。

## 解码策略

解扰始终使用原始条带坐标。JPEG 和超预算 PNG 按条带区域采样；预算内 PNG 一次解码，避免逐区重复扫描 PNG 行。该选择来自本机实测，不能把“区域解码”一概视为更快。

PNG 完整路径的输入与输出 Bitmap 总预算为堆上限四分之一且最多 64 MiB；低内存设置收紧到堆上限八分之一且最多 16 MiB。输出受屏幕宽度、4096 高度，以及最多 32 MiB/堆上限八分之一的输出预算共同约束。全局解码执行并行度为一。普通图片继续使用 Coil，GIF 由 `coil-gif` 处理。

离线文件优先复用；复制完成后回收阅读缓存里的同一份字节，一个页面在磁盘上只保留一个文件。原解扰实现仅保留在 androidTest 中，作为可重复的对照；它不进入应用运行包。

## 验证

构建与静态检查：

```powershell
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug :app:testDebugUnitTest :core:network:testDebugUnitTest :core:database:testDebugUnitTest
```

模拟器测试类位于 `app/src/androidTest/java/com/ppxb/miwaku/refactor`，使用隔离目录、合成图片和本地服务器，不需要真实账号。网络测试显式直连环回地址，避免设备代理影响。仅 debug 配置允许 localhost 明文 HTTP。

测试覆盖旧数据导入与幂等、损坏清单、逐章状态、写入失败恢复、未读入队、过期会话、窗口有界、真实 Compose 换章/分页、响应体取消、请求复用/优先级、文件回退及解扰边界。

`DecoderBenchmarkTest` 对同一批合成 PNG/JPEG 交替执行原始完整 Bitmap 路径与新解码器，每种场景预热两次、记录十次。指标是独立解码阶段耗时和本实现持有的 Bitmap 峰值，不包括解码器内部、GPU、整进程内存，也不代表整个应用的提速比例。

测试输出、解码测量与直接操作截图保存在 `build/reports/reader-refactor/`。

2026-10-30，Android 15、1080×1920、192 MiB 堆上限的模拟器：5555 与 16384 两个 ADB 端口分别执行全部 22 项测试，均通过。直接操作确认页中间返回后可以恢复偏移，章尾真正显示后详情才变为已读。数据层、图片请求与阅读窗口均完成只读子代理复核。

5555 端口的独立解码测量（每项十次样本）：

| 图片 | 原路径 P50/P95 毫秒 | 新路径 P50/P95 毫秒 | 原/新 Bitmap 峰值 MiB |
|---|---:|---:|---:|
| PNG 720×1080 | 7.42 / 12.63 | 7.46 / 12.82 | 5.93 / 5.93 |
| JPEG 720×1080 | 2.74 / 4.39 | 3.96 / 5.62 | 5.93 / 3.26 |
| PNG 720×16000 | 74.48 / 76.60 | 76.52 / 77.93 | 46.82 / 46.82 |
| JPEG 720×16000 | 27.15 / 27.77 | 20.32 / 20.94 | 46.82 / 3.97 |

普通 JPEG 在这组样本中多约 1.2 毫秒，换取较低的瞬时 Bitmap 分配；长 JPEG 的耗时和分配均下降。PNG 保留预算内完整解码，避免全区域扫描曾测得的约四倍耗时。另有 512×80000 PNG 的流式生成测试，验证超预算时使用区域解码，解码器持有的 Bitmap 峰值低于 2 MiB。
